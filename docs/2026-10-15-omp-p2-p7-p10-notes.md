## P2（T8a）strategy replay 的 B(B−1)/2 ramp — **未實作，但收斂了唯一解**

### 已確認（讀碼 + 既有歸因交叉驗證）

1. `strategy.ts:881` `simAt(ctx, uptoBar)` 的備忘快取是 `{count: orders.length, byBar: Map<uptoBar, Sim>}`（`:877`）。
   `cache.count !== orders.length` 就把整個 `byBar` 丟掉（`:887`）。
2. **但 epoch 丟棄造成的重算是 0 步**（既有歸因：`epochRebuildSteps` 0/0/0）。所以 ramp 的來源**不是** epoch 丟棄，而是 build 趟對 100 個**互異** `uptoBar` 各自從 0 算一次：
   Σ_{N=0}^{B−1} N = B(B−1)/2 = 4,950 / 19,900 / 124,750 —— 與歸因表逐字相符。
3. ⇒ **任何「保留快取跨 epoch」的修法都無效**（那些條目本來就會 miss，反而是被丟的那批貢獻 0）。唯一能降階的是**讓 `simulate(N)` 由 `simulate(N−1)` 續跑一根**。
4. 續跑**在語意上成立**：`simulate` 的迴圈本體在 bar `b` 用到 `uptoBar` 的地方全是 `lowAt/highAt/openAt/closeAt/timeAt(ctx, b, uptoBar)` 型讀取，對 `b ≤ N` 而言其值與 `N` 無關（`uptoBar` 只是上界）。所以 bar `b` 的步進對所有 `N ≥ b` 是同一個函數。

### 為何不在本輪實作

- `simulate` 是 700+ 行純函數（`strategy.ts:295` 起），要把它的**全部迴圈區域狀態**（部位、pending、riskWalk 游標、day 邊界、execs 累積…）抽成顯式 cursor 才能續跑。這是實質演算法重構，不是外掛快取。
- 驗收要求「四支 digest 不變＋`s1-inc-probe` parity 6/6＋golden 0 差異」——任何語意漂移都會被這些抓到，但**改壞的代價高**（交易語意）。
- 期間窗 C 並行在改 `interpreter.ts`／`mtf.ts`／`series.ts`，且無法取得安靜機量測 ⇒ 無法用「replaySteps 降為 O(B)」的帳面數字驗證。

### 建議的實作形狀（若接手）

```
介面：SimRun = { bar: number; sim: Sim; /* 其餘迴圈區域狀態 */ }
simulateRun(ctx, orders, cfg, run: SimRun, to: number): SimRun   // 續跑到 to
simAt：byBar 改存 SimRun（而非 Sim）；查 uptoBar 時取「≤ uptoBar 的最大已存 run」起跑
驗收：replaySteps 由 B(B−1)/2 → O(B)；四支 digest 逐字不變；parity 6/6；golden 0
```
