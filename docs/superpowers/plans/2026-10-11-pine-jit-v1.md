# Pine JIT Transpiler — REAL PLAN v1
2026-10-11 · task-workflow P5

## 目標
K4.55 (935 bars) browser 載入 11-13s → <2s（≥5x）。Interpreter dispatch 瓶頸 1.34M evalNode → codegen 後降到 ~50-100K。

## 證據回顧
- evalNode 總數 1.34M/2000bars = ~670 calls/bar
- compiled closure vs evalExpr 只差 ~20% — 瓶頸在 closure 內共用機器不在 AST walk
- Scout 確認：scope/bindDeclared/call dispatch/fallback envelope 都必須保留

## 架構

```
parse(src) → body: Node[]
jitCompile(body) → { src, nodeTable, native, fallback }
new Function('R','J','__nodes', src) → fn(R, J, nodeTable)
per bar: fn(...) — each stmt = 1 JS statement; non-transpilable → R.evalStmt(idx)
```

**Runtime (R.* shim, src/pine/jit.ts)** — thin wrappers, semantics 100% 沿用 interpreter：
- `R.ident(name)` — evalIdent minus node dispatch
- `R.decl(key,name,thunk)` — bindDeclared(run,key,scope,name,thunk(),bar)
- `R.varDecl(key,name,thunk)` — twoPhase：fresh → bindDeclared(persistent) ; later → cow/slot rebind
- `R.set(name,thunk)` — evalReassign 邏輯（scope.lookup→setAt）
- `R.hist(name,idx)` — BarSeries.get(idx) on the slot
- `R.member(obj,prop)` — evalMember 邏輯（UDT fields / builtin ns / drawing props）
- `R.binary/unary/ternary/and/or/truth` — evalBinary/evalUnary/unseriesTruth
- `R.pushScope()/popScope()` — blockFrame equivalent (new Scope(parent))
- `R.evalStmt(idx)` — `evalExpr(nodeTable[idx], frame)` with proper topStmtIdx/topLevelBody/scopeDepth bookkeeping
- `R.call` **不在 v1** — all call stmts/exprs fallback to evalExpr first

## Slices

### Slice A — jit.ts codegen + runtime (DONE skeleton, needs runtime impl)
- codegen: literals/ident/unary/binary/ternary/arraylit/histref(ident)/member/assign/let/const/typed/var/reassign/if/seq
- runtime: R.* helpers 全走 interpreter 內部 fns（`evalIdent`,`bindDeclared`,`slotFor`,`evalReassign`,`evalMember`,`evalBinary`,`unseries`,`unseriesTruth`,`histGetAt`,`evalHistref`,`Scope`,`evalExpr`,`evalBlock`）
- 必要 export: interpreter 需要把上面 fns export（已大多 export 或同 module 可 internal）
- file: `src/pine/jit.ts` (新建) + interpreter.ts 加 `runJit()` entry

### Slice B — host integration
- `runJit(body, frame, run)` in interpreter.ts：
  - `const { src, nodeTable } = jitCompile(body)`
  - `const fn = new Function('R','J','nodes', src)` (cached per source)
  - bar loop: `run.topLevelBody=true; run.topStmtIdx=i; try { fn(R, J, nodeTable) } catch ...`
  - `R.evalStmt(idx)` calls `evalExpr(nodeTable[idx], frame)` — same as Slice-D fallback envelope
- Env knob: `__pineJit` (default ON when true; `__pineInterp`仍控制 compiled-vs-evalExpr)

### Slice C — A/B harness + tests
- `scripts/scratch/bench-jit.ts` — K4.55 跑 jit vs compiled vs interp, report ms + native/fallback 比例
- `src/pine/__tests__/jit.test.ts` — parity: snapshot(runScript with jit) === snapshot(compiled) on compile.test.ts CORPUS subset
- 必須不變：__compiledKinds, __mtfStats, __evalNodeCounts, error line/col

## 風險
- R1: `new Function` 在 worker CSP — 需實測；如禁則走 `eval()` in worker（同樣限制）或 WebAssembly compile
- R2: 非 transpilable stmt 密度高 → 收益不足；K4.55 實測 native/fallback 比例決定 ROI
- R3: scope shadow + UDF closure — blockScope 必須正確接續 parent chain
- R4: CowSeries/paramCows 在 JIT path 的 siteKey 一致性 — siteKey(run,node) 已用 AST node 作 WeakMap key，JIT 的 N(n) 同 index 但需確認 siteKey 走 node identity 而非 index
