## P0 需求

- 需求：`runScript` 搬進 Web Worker；主執行緒不被重 script 阻塞；輸出與 in-process 一致。
- 驗收：① vite 產 worker chunk、browser smoke 產出同 model ② stop() 中止 worker run ③ fetchSeries 走 RPC ④ 非 cloneable Value 不炸 ⑤ vitest 全綠 + 無 Worker 時 fallback in-process ⑥ 不造第二套 RPC convention。
- 非目標：不改 interpreter 內部、不做 SAB/zero-copy、不做 worker pool。

## 協議（契約定稿）

```ts
// ToWorker
{ t:'run', id, source, bars: BarData[], opts:{ symbol?, timeframe?, inputValues?, syminfo?, hasFetch:boolean } }
{ t:'abort' }                                   // 同時只有一個 run in flight（drain 序列化）
{ t:'fetchRes', fid, ok, bars?: BarData[], error? }
// FromWorker
{ t:'fetchReq', fid, sym, tf }
{ t:'done', id, result /* sanitized RunResult */ }
{ t:'fail', id, error:{ name, message, stack?, line?, col? } }
```

- worker 端 `createWorkerHandler(post)` 純函式回傳 msg handler —— FakeWorker 測試直接呼叫，真 entry 是 `onmessage = handler`。
- abort：worker `aborted` flag，`shouldAbort: () => aborted`，run 入口 reset。
- fetch：worker 端 `fetchSeries = (sym,tf) => new Promise(...)` pending map by fid。
- sanitize：worker 端 done 前跑 `sanitizeRunResult`。

## sanitize 白名單（RiskBoundary 核對）

- Value：na/int/float/bool/string/color 淺拷貝；array/matrix 遞迴；map → `new Map` 遞迴 entries；udt → `{typeName, fields:new Map}`；series → `v.cur()` 再 sanitize；function/void → NA；line|label|box|table|polyline|linefill → DrawObj props generic walk（primitives/Array/Map/plain obj 遞迴；Value-shaped（有 `kind`）→ sanitizeValue；其他 class instance → null）。
- RunResult 其他欄位全 cloneable（bgcolors/barcolors/execs/alerts/alertconditions/warnings/inputs/props/title/shorttitle/overlay）。

## 執行結果（2026-10-09）

實作：worker entry `pineWorker.ts`（`createWorkerHandler` 純函式 + DedicatedWorkerGlobalScope 守衛）、client `pineWorkerClient.ts`（lazy spawn、fetchReq/fetchRes RPC、worker-error → unavailable）、`pineMarshal.ts` sanitize（白名單遞迴 + path-scoped cycle guard）、`engine.ts` 抽 `sessionRunner/runProgram/abortRun` seam、`PineWorkerEngine`（**per-session client**）、`velaPineEditor.ts` re-export 切換。

Review 三視角抓到並已修：
- **Critical**：per-engine 共享 client 會丟第二個 `execute()` session 的 run（'run in flight'）、且 session A 的 stop() 會殺 B 的 worker → 改 per-session client。
- fetchReq 回應發給重生 worker → fetchReq 時捕獲 worker 參考（fid 碰撞餵錯資料的洞）。
- transport error 不設 unavailable → spawn→crash 無限迴圈 → 已設。
- postMessage 同步 throw 殘留 pending → try/catch。
- sanitize 無 cycle guard（udt 自指 RangeError）+ Map key 未 sanitize + kind 啟發式碰撞 → 已修。
- 'abort' 訊息是死碼（terminate 丟棄 task queue）→ 協議移除，stop=terminate。
- fetchReq 在無 pending run 時仍執行 fetch → pending null 回 ok:false。
- importScripts 守衛過寬 → DedicatedWorkerGlobalScope instanceof。

驗證：vitest 27 新測綠（marshal 20 + workerEngine 7，含多 session 回歸）、全套件綠、tsc 無新錯、browser smoke（:5173 真 worker chunk、close*2 正確、fetchSeries RPC 通、雙 session 並行）。
